# Wave 2: what changed since Wave 1

**What this proves: the mechanics, on testnet. No real users or mainnet collateral claimed.**

Mezo Agent Toolkit, Track 2: Access and Distribution, Wave 2 entry. Mezo testnet only (chain 31611). Baseline: the last Wave 1 commit, `86526cb` (2026-10-26). The before-and-after table is in the [README](../README.md#what-changed-since-wave-1). Dates: 11 of the 16 transactions below were sent on 2026-10-31, 3 on 2026-11-05 and 2 on 2026-11-12, so this page says "since Wave 1", not "during Wave 2".

## What the Wave 1 judge asked

The Wave 1 judge (`civ_defi_mezo`, 2026-10-30), quoted in full:

> Your MezoLens is a solid protocol-aware read layer (trove health, redemption queue, pool quotes, ve locks), which puts Integration at L3; to go higher in Wave 2, have the agent act on Mezo primitives, for example top up or repay a trove through BorrowerOperations, deposit to the Stability Pool, or ship the planned veBTC/veMEZO gauge vote helper, with real on-chain transactions from the product. All 41 MUSD payments so far are your own test traffic, so getting even a few outside agents or sellers paying in MUSD would strengthen both Integration and Product. A clearer business case (who pays and why, when the same reads are free through the MCP tools) and an installable MCP package that runs without cloning the repo would lift Product and UX.

## Not done

- **No outside payer.** 0 outside wallets have paid (above).
- **No shared settlement ledger across Worker instances.** The Worker's memory of which payments it already served is per instance ([README, Limits](../README.md#limits-stated-plainly)).
- **Cloudflare's limits were not measured on Cloudflare.** The request counts are from Node and from the code ([README, Limits](../README.md#limits-stated-plainly)).
- **`pay_and_fetch` spend limits reset when the server restarts.** The write tools' daily cap survives a restart (it is re-read from the receipts file).
- **No extra pool quotes in the lens.** `MezoLens` has the same functions as in Wave 1 apart from the live-veBTC change.
- **No veMEZO vote helper.** Voting is built for veBTC only.
- **`sp_withdraw` and `approve_revoke` have not sent a real transaction.** The pool refused every withdrawal and no allowance was left open ([README, Limits](../README.md#limits-stated-plainly)).
- **Not on the npm registry, not on the MCP registry.** The v0.2.0 release asset does not contain the review fixes; the v0.2.1 asset does.
- **Nothing on mainnet.** Every transaction is on testnet; 15 were sent by our wallet and the 16th by the x402 facilitator for our wallet.
